# Case Study Content Structure

Setiap project penting punya halaman detail sendiri.

## Header

Fields:
- Project Name
- One-line product description
- Period
- Role
- Platform
- Stack
- Project Type
- Hero image

## 1. Context

Jawab:
- Produk ini apa?
- Dipakai untuk apa?
- User atau konteks operasionalnya siapa?

Gunakan bahasa non-teknis dulu.

## 2. My Role

Harus jelas apa yang benar-benar Ark kerjakan.

Contoh untuk PUAS:

> I owned the Flutter application from initial development through final delivery, covering UI implementation, API integration, transaction flows, printer integration, debugging, and release preparation.

## 3. What I Built

Pilih 4–6 hal penting saja.

Jangan jadi daftar semua fitur.

## 4. Engineering Decisions

2–4 keputusan yang memang nyata.

Examples:
- transaction state handling
- reusable tenant structure
- API contracts
- database structure
- device integration
- error/retry flow
- release workflow

## 5. Integrations

Jika relevan:
- REST API
- payment system
- QRIS
- NFC
- Bluetooth
- Printer
- Maps / Location
- Firebase
- Supabase
- AI APIs

## 6. Challenges

Tulis problem engineering nyata.

Hindari drama palsu.

## 7. Result

Gunakan outcome faktual.

Examples:
- Delivered until final project completion.
- Released through Play Store/App Store.
- Used across multiple tenant applications.
- Supported merchant transaction workflows.
- Created a reusable base for subsequent features.

Jangan invent:
- conversion %
- revenue
- user count
- latency improvement
- cost reduction

## 8. Stack

Compact stack list.

## 9. Links

Optional:
- GitHub
- Live Demo
- Store Link

Hanya tampilkan jika benar-benar tersedia.
